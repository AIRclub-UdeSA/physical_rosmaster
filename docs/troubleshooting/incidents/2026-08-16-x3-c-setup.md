# 2026-08-16 x3-c Setup Incident

## Summary

Robot: `x3-c`

Scope: initial physical setup inside `rosmaster_humble` on ROS 2 Humble.

This incident seeded the troubleshooting knowledge base for future robots. It covers the exact failures observed during the robot bringup and the corresponding verification steps.

## Observed Problems

- Docker failed with an OCI runtime error because the host `runc` binary was corrupted.
- The old flat Yahboom source tree caused duplicate package discovery when it stayed under the colcon workspace root.
- The installed `Rosmaster_Lib` on `x3-c` was verified to match public V3.3.9.
- A clean clone exposed a build assumption in `yahboomcar_slam`: missing optional `pcl` artifacts broke `install(DIRECTORY ...)`.
- A stale `yahboomcar_slam` entry remained in generated install state after the failed build.
- Hostname resolution still prints `sudo: unable to resolve host x3-c` and should be fixed separately on the Raspberry Pi host.

## Fixes Applied During Setup

- Reinstalled `containerd.io` on the Raspberry Pi host to repair `/usr/bin/runc`.
- Removed the backup `src` tree from the colcon workspace after cloning the Git repository.
- Verified the installed `Rosmaster_Lib` hash against the public V3.3.9 reference.
- Updated the workspace so `yahboomcar_slam` no longer requires missing optional `pcl` files during install.
- Rebuilt generated state after the failed SLAM build.

## Verification State

- 18 normal packages built successfully when `yahboomcar_slam` was skipped.
- The optional-artifact build issue is now documented and guarded in the repository.
- Manual motion validation and stationary encoder probing remain the next hardware checks.

## Stationary Probe Result

Observed on `x3-c` with the robot stationary:

- `motion_vx`, `motion_vy`, and `motion_vz` stayed at `0.000000` for all 100 samples
- encoder counters stayed constant at `-3, 2, 1, 90`
- reported battery voltage stayed around `10.5` to `10.6` V
- no serial errors were reported during the probe

## Follow-Up

- Keep autostart disabled until manual bringup and hardware validation pass.
- Fix the host `/etc/hosts` mapping outside the container.
- Continue odometry validation from `docs/odometry_validation.md`.
